# Cambios Realizados al Frontend (`docs/CAMBIOS_FRONTEND.md`)

Todos los cambios realizados al frontend respetan el framework (React 19 + TypeScript + Vite + Tailwind CSS + Zustand), las rutas, los componentes y el diseño visual original. Únicamente se conectaron los servicios, el streaming en tiempo real y los estados de carga/error al backend FastAPI.

| Archivo | Qué cambió | Por qué |
|---|---|---|
| `.env` / `.env.example` | Se definió `VITE_API_BASE_URL` (por defecto `http://localhost:8000` en local y vacío tras proxy Nginx en Docker). | Configurar la URL base de la API mediante variable de entorno sin quemar URLs en el código. |
| `src/services/httpClient.ts` | Nuevo cliente `fetch` centralizado con soporte de token Bearer, cabecera `X-Demo-Role` y descarga de archivos (`/export`). | Centralizar llamadas HTTP, manejo de errores y autenticación JWT. |
| `src/services/api/ApiAuthService.ts` | Cliente para `/auth/demo-session` y `/auth/me`. | Obtener sesión JWT real según el rol seleccionado en `LoginPage` o `Header`. |
| `src/services/api/ApiCatalogService.ts` | Cliente para `/offices`, `/staff`, `/settings/rules`, `/reports/summary` y acciones de refuerzo/liberación de sede. | Reemplazar catálogos locales (`INITIAL_OFFICES`, `INITIAL_STAFF`) y métricas estáticas de reportes. |
| `src/services/api/ApiDigiturnoService.ts` | Implementación real de `IDigiturnoService` más endpoints `/digiturno/network-load`, `/user-behavior` y `/office-daily-activity`. | Consumir métricas vivas, carga de red y comportamiento histórico desde PostgreSQL. |
| `src/services/api/ApiAusenciasService.ts` | Implementación real de `IAusenciasService` con recálculo inmediato de plan, alertas y redistribuciones. | Persistir ausencias en BD, aplicar Ley 1581 en servidor y recibir plan recalculado (< 5 s). |
| `src/services/api/ApiTurnosService.ts` | Implementación real de `ITurnosService` más validación de casillas (`/slots/validate`) y generación de plan (`/plans/generate`). | Persistir mallas, ediciones manuales, restauraciones y aprobaciones con auditoría. |
| `src/services/api/ApiMotorService.ts` | Implementación real de `IMotorService` más pronóstico, mapa de calor, comparativas, picos y redistribuciones (`/accept`, `/reject`). | Delegar pronóstico, Erlang C/A, SimPy y PuLP MILP al backend Python. |
| `src/services/index.ts` | Se cambiaron las instancias activas de `Mock*Service` por `Api*Service`. | Conectar la capa de contratos del frontend al backend real sin alterar las pantallas. |
| `src/store/useAuthStore.ts` | Se añadió `token`, `initSession()` y `setRole()` asíncrono con `/auth/demo-session`, registrando proveedores en `configureHttpAuth`. | Enviar JWT del rol activo al backend para RBAC y filtrado Ley 1581. |
| `src/store/useAppStore.ts` | Se eliminaron `INITIAL_OFFICES`/`INITIAL_STAFF`, se cargan datos iniciales desde FastAPI, se añadió `error` y conexión **SSE** (`/realtime/stream`), y se conectaron todas las acciones (`acceptRedistribution`, `rejectRedistribution`, `dismissAlert`, `updateOffice`, `updateRules`, `requestOfficeSupport`, `releaseOfficeStaff`, `reloadAbsences`). | Eliminar mocks en memoria y alimentar el dashboard en tiempo real vía SSE sin recargar. |
| `src/components/layout/AppLayout.tsx` | Se desconecta SSE al desmontar y se muestra banner de error con botón `Reintentar` si `error` está presente. | Manejo explícito de errores de red y limpieza de suscripción SSE. |
| `src/components/layout/Header.tsx` | Se eliminó el polling local `setInterval(tickSimulation, 5000)` (reemplazado por SSE en el store) y al cambiar de rol se recargan ausencias (`reloadAbsences`). | Evitar polling redundante y demostrar filtrado Ley 1581 desde el servidor al cambiar rol. |
| `src/components/dashboard/LiveQueueChart.tsx` | Reemplaza cálculo local de `predictArrivals` por `networkLoad` proveniente del store. | Mostrar la curva agregada real de las 14 oficinas calculada en el backend. |
| `src/components/dashboard/UserBehaviorWidget.tsx` | Reemplaza arreglo estático de trámites y tasa `1.3%` por `userBehavior` del backend. | Mostrar distribución y tasa de abandono reales del histórico Digiturno. |
| `src/pages/LoginPage.tsx` | `handleLogin` ahora espera `await setRole(selectedRole)` antes de navegar al dashboard. | Garantizar que el token JWT del rol elegido esté listo antes de cargar datos protegidos. |
| `src/pages/DayPlanPage.tsx` | Usa `peaksSummary` del backend en Paso 2, conteo/déficit dinámico en Paso 1, `slaProyectadoRed` real en Paso 5 y `navigate('/malla')` en Paso 3. | Eliminar textos y cifras quemadas en JSX y evitar recarga completa de SPA. |
| `src/pages/ShiftGridPage.tsx` | Usa `operatingSlots` y `requiredAgentsByOffice` del backend y valida cambios manuales vía `apiTurnosService.validateSlot`. | Sincronizar la malla con las 19 franjas reales (`07:00–16:00`) y requerimientos Erlang C del servidor. |
| `src/pages/RedistributionPage.tsx` | Calcula el KPI de espera reducida desde el impacto real devuelto por el backend (sin fallback `8.5`). | Eliminar cifra quemada cuando las recomendaciones están pendientes. |
| `src/pages/OfficeDetailPage.tsx` | Carga pronóstico y actividad diaria desde la API y conecta `Pedir Refuerzo Virtual` y `Liberar Personal` al backend. | Eliminar `predictArrivals` local y persistir acciones de sede con auditoría. |
| `src/pages/DemandAnalysisPage.tsx` | Consume `getHeatmap`, `getFortnightComparison` y `getOfficeComparison` desde la API con columnas dinámicas según `operatingSlots`. | Alimentar mapas de calor y comparativas desde el histórico real de Digiturno. |
| `src/pages/SimulatorPage.tsx` | Consume `curvaErlang` y abandono real desde `POST /api/v1/simulation/run` y conecta `Convertir en Propuesta de Plan` a `/simulation/apply-scenario`. | Usar simulación SimPy + Erlang A del backend en lugar de cálculos locales en navegador. |
| `src/pages/ReportsPage.tsx` | Consume `GET /api/v1/reports/summary?range=...` y descarga CSV desde `GET /api/v1/reports/export`. | Mostrar KPIs reales calculados por el backend según rango y exportar desde el servidor. |
| `src/pages/SettingsPage.tsx` | Sincroniza `systemRules` con `GET/PUT /api/v1/settings/rules`, persiste edición de oficinas con `PATCH /api/v1/offices/{id}` y añade carga `.xlsx` al endpoint ETL con resumen de calidad. | Hacer persistentes las configuraciones en PostgreSQL y permitir ingesta de Digiturno desde la UI. |
| `src/pages/SimulatorPage.tsx` | Consume `curvaErlang` y abandono real (`abandonoActualPorcentaje`/`abandonoSimuladoPorcentaje`) desde `POST /api/v1/simulation/run`, muestra nota de modelado Erlang/SimPy y conecta `Convertir en Propuesta de Plan`. | Mostrar espera y abandono antes vs. después del simulador SimPy del backend. |
| `src/components/redistribution/RecommendationCard.tsx` y `src/pages/RedistributionPage.tsx` | Muestra abandono antes vs. después en el bloque de impacto y añade botón discreto de edición (`PATCH /api/v1/redistributions/{id}`) con auditoría. | Permitir editar modalidad/franjas antes de aceptar y visualizar impacto en abandono. |
| `src/pages/ShiftGridPage.tsx` y `src/pages/AbsencesPage.tsx` | Añade botones discretos de exportación `.xlsx` (malla y ausencias) e importación `.xlsx` de ausencias manteniendo intacta la estética. | Cubrir el flujo completo de importación y exportación Excel requerido para la coordinadora. |
| `src/components/dashboard/LiveQueueChart.tsx` | Añade `isAnimationActive={false}` sobre las series `Area` y consume `networkLoad` del backend. | Asegurar render inmediato de las dos curvas completas sin recortes visuales. |

> **Nota sobre mocks residuales:** Los archivos en `src/mock/` y `src/services/mock/` **ya no son importados por ninguna pantalla, componente ni store en tiempo de ejecución**; se conservan únicamente para no romper los tests unitarios legacy de `src/engine/*.test.ts`.
